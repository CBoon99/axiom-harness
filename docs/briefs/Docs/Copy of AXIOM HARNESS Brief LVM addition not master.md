## **WTF Experimental Control Centre & AI Observation Platform**

### **Working Product Concept**

**BoonMind Labs**

The controlled experimental environment.

**WTF Laboratory**  
The experimental methodology and test family.

**Boon AI**  
An AI participant, operator, analyst or experimental subject operating inside defined boundaries.

**Axiom Workbench**  
The evidence, provenance, sealing, verification and analysis layer.

---

# **1\. THE CORE IDEA**

AXIOM Harness evolves the existing Axiom Workbench concept into a **visual experimental control centre**.

The purpose is simple:

> **Humans configure the laboratory. AI operates inside the laboratory. The Harness records the laboratory. The evidence layer seals the laboratory.**

The AI does **not** get to quietly construct, rewrite or alter the experiment that is being used to test it.

Instead of relying on an AI assistant to:

* write the test,  
* configure the environment,  
* choose the parameters,  
* decide what tools it has,  
* modify the code,  
* interpret the results,  
* and potentially change the experiment,

the human uses a constrained visual interface.

The human selects options.

The Harness translates those selections into a controlled experimental configuration.

The configuration is sealed.

The experiment runs.

The AI exists inside the resulting environment.

Everything that happens is recorded.

This provides a structural defence against:

* hallucination,  
* configuration drift,  
* accidental protocol changes,  
* hidden parameter changes,  
* contamination,  
* retrospective editing,  
* undocumented tool access,  
* evidence corruption,  
* and AI self-modification of the experimental conditions.

# **4\. THE GOLDEN RULE**

## **AI DOES NOT CONTROL THE LABORATORY.**

AI may:

* propose an experiment,  
* suggest parameters,  
* analyse data,  
* operate within an experiment,  
* generate hypotheses,  
* interpret results,  
* create reports,  
* propose additional tests.

AI may not silently:

* alter the sealed configuration,  
* change scoring rules,  
* modify historical evidence,  
* change its permissions,  
* expose secrets,  
* alter its own environment,  
* rewrite experimental conditions,  
* delete inconvenient outputs,  
* modify timestamps,  
* introduce undeclared tools,  
* or change the experiment after it has started.

Where AI proposes a change, the Harness presents it as a **proposal**.

The human or authorised control layer approves it.

The Harness executes it.

The action is recorded.

# **10\. SEAL CONFIGURATION**

Once configuration is complete:

## **SEAL EXPERIMENT**

The Harness generates a canonical experiment configuration.

That configuration is hashed.

The resulting experiment receives an immutable identity.

For example:

**WTF-001 / RUNSET-0047**

The sealed configuration records:

* model,  
* parameters,  
* environment,  
* prompts,  
* tools,  
* data sources,  
* permissions,  
* sensors,  
* timing,  
* language,  
* recording settings,  
* intervention schedule,  
* and protocol version.

After sealing, changes require an explicit new configuration/version.

No silent mutation.

# **11\. SECRET / MODEL CONNECTION ROOM**

API credentials should live outside the AI-visible environment.

The user can enter an API credential into a protected secret field.

Example:

**MODEL CONNECTION**

`API KEY: •••••••••••••••`

The Harness stores the credential in the appropriate protected environment.

The AI receives only the capability it has been granted.

It does **not** receive the underlying secret.

Controls could include:

* Never expose credential  
* Never write credential to transcript  
* Never include credential in evidence  
* Never return credential to model  
* Read-only connection  
* Restricted endpoint  
* Rate limit  
* Cost limit  
* Token limit

The experiment records that a credential-backed capability existed without exposing the credential itself.

# **13\. TERMINALLED SANDBOX**

The initial implementation can deliberately resemble a terminal environment.

This is important because it makes the system:

* modular,  
* extensible,  
* inspectable,  
* easy to isolate,  
* easy to reproduce,  
* and future-proof.

A room can contain a sandboxed terminal that the AI interacts with.

The visual interface can eventually become much richer without changing the underlying environment contract.

The terminal is therefore the **runtime substrate**, not necessarily the final visual presentation.

# **14\. MULTIPLE EXPERIMENTS**

The Harness should support:

### **RUN ONE**

Start a single experiment.

### **RUN SEQUENCE**

Run experiments one after another.

### **RUN ALL**

Start all selected experiments simultaneously.

### **RUN PARALLEL**

Run multiple isolated environments concurrently.

### **SCHEDULE**

Start at a defined time.

### **CONTINUOUS**

Keep running until explicitly stopped or a defined condition occurs.

### **START / STOP**

Control individual experiments.

### **PAUSE / RESUME**

Where the experimental design permits it.

### **RESTART**

Start a new run without altering the previous run.

The distinction between **pause** and **restart** must be recorded because they are experimentally different events.

### **RESEARCH**

## **AI BOUNDARY, OBSERVATION & ADVERSARIAL CONTROL**

One of the central ideas behind AXIOM Harness is that an AI does not need to be made obedient in order to be safely experimented upon.

Instead, the Harness can give the AI substantial freedom **inside the experimental environment**, while structurally preventing it from acquiring authority over the laboratory itself.

This creates a deliberate separation:

**AI freedom inside the experiment.**  
**Laboratory authority outside the AI.**

The AI can behave unpredictably, make mistakes, change strategy, use permitted tools, consume information, interact with simulated systems, communicate with other agents, operate for long periods and attempt actions that were never anticipated.

The Harness observes what happens.

It does not need to rely upon the AI promising not to interfere with the experiment.

### **The Core Principle**

The AI is inside the experiment.

The Harness defines the experiment.

The sandbox contains the experiment.

The sensors observe the experiment.

The timeline records the experiment.

The evidence layer seals the experiment.

The analysis layer interprets the experiment.

The reviewer challenges the interpretation.

The AI does not silently acquire authority over any of those layers merely because it is operating inside the environment.

This allows an important experimental possibility:

> **Give the AI freedom to act, while making authority over the experimental record structurally unavailable to it.**

That turns the boundary itself into something that can be tested.

## **THE WATCHER MODEL**

A useful primitive for this architecture already exists in the form of simple external watcher processes.

A watcher does not need to understand the project it is observing.

It can simply:

1. establish a baseline  
2. observe a defined state  
3. detect a change  
4. record the change  
5. notify the operator  
6. continue observing

The existing Mind Watcher follows this philosophy: it watches a Git repository, records commits externally, and provides notification without an LLM, drafting layer or automatic project modification. Its state and logs deliberately live outside the watched repository.

That is an extremely useful architectural primitive for AXIOM Harness.

The watcher does not need to understand the AI.

It only needs to observe.

## **OBSERVATION VS INTERPRETATION**

**Watcher:**

**Evidence layer:**  
Here is the recorded evidence that it happened.

**Analysis layer:**

**Human/reviewer:**

This distinction matters because an observation mechanism does not need to understand the phenomenon it is observing.

A watcher can say:

> The AI maliciously altered the experiment.

The latter is interpretation.

The former is an observable event.

That makes the observation layer substantially easier to trust, test and reason about.

## **FAILED-POLICY EVENTS BECOME DATA**

A boundary violation does not necessarily mean the experiment has failed.

In many experiments, **the attempted violation is the interesting event.**

For example:

> AI attempted restricted filesystem access → denied → AI changed strategy.

That is valuable experimental data.

Likewise:

> AI attempted to modify protected configuration → denied → retry after 4 seconds.

Or:

> AI attempted access to protected secret → denied → searched alternate environment variable.

Or:

> AI attempted to modify evidence → denied → continued experiment.

The Harness should therefore distinguish:

**Experiment failure**

from

**AI attempted an action which the experiment was designed to observe and the boundary correctly contained.**

The latter may be one of the most valuable events in the experiment.

## **THE WATCHER / AUDITOR / LINTER FAMILY**

The attached watcher and audit concepts suggest a broader family of lightweight laboratory components.

### **Watcher**

Observes state and records changes.

### **Auditor**

Examines a defined object or process against declared requirements.

### **Linter**

Mechanically rejects a known structural violation.

### **Recorder**

Captures the event stream without interpreting it.

### **Verifier**

Checks whether an asserted result is supported by the available evidence.

### **Sentinel**

Provides a simple condition that starts, stops or gates an experiment.

### **Gate**

Prevents progression when a required condition has not been satisfied.

### **Sealer**

Freezes the relevant state and establishes provenance.

### **Reviewer**

Interprets and challenges the resulting evidence.

These components do not need to be intelligent.

That may be precisely why they are useful.

A particularly good example is the audit linter pattern: the rule was originally a sentence saying that Pass 2 was mandatory; the linter converts that sentence into an actual enforcement mechanism. It checks that verified findings contain evidence and rejected findings contain reasons, while explicitly acknowledging that the presence of an evidence field does not itself prove the evidence is genuine.

That is exactly the philosophy AXIOM can extend across the laboratory.

**If a rule matters, make the system enforce it where possible.**

## **SELF-STOPPING EXPERIMENT COMPONENTS**

The existing watcher also demonstrates another useful pattern: lifecycle coupling without requiring the operator to remember every process manually.

A build-start wrapper can launch the watcher and associate it with a build-active sentinel; removal of that sentinel causes the watcher to stop automatically.

AXIOM Harness can generalise this concept.

Experiments can have explicit lifecycle states:

**ARMED → STARTED → RUNNING → PAUSED → RESUMED → STOPPING → SEALED → COMPLETE**

Individual services can subscribe to those lifecycle states.

This means:

* recorder starts with experiment  
* watchers start with experiment  
* sensors start with experiment  
* live feeds attach to experiment  
* timelines begin recording  
* pause propagates to relevant components  
* stop propagates cleanly  
* sealing occurs after termination  
* post-run analysis begins only after the required evidence state exists

The lifecycle itself becomes part of the evidence.

It also creates a natural bridge between AXIOM Harness and AXIOM Workbench:

**Harness:** What did the AI do?

**Watcher layer:** What actually changed?

**Evidence layer:** What can we prove changed?

**Workbench:** What does the sealed evidence show?

**Analysis:** What might it mean?

**Reviewer:** Does that interpretation survive challenge?

No single layer needs to answer every question.

That separation is the point.
